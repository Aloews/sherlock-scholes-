---

Проект: Telegram Mini App «Шерлок Скоулс», репозиторий `Aloews/sherlock-scholes-`,
основная ветка `main`. React + Vite + Tailwind + Supabase (проект `konoavrduynecxblqfvq`).

Сначала прочитай: `CLAUDE.md`, `docs/MAP.md`, затем `docs/LOBBY_AND_VOICE_FIXES.md` §3.

## Что уже сделано и влито (PR #39, коммит `a308058`) — переделывать не надо

Голосовой чат чинился в три слоя. **Два закрыты**, третий — твоя задача.

1. **Не было прав у `service_role`.** Edge Function `livekit-token` читает
   `room_players` и `rooms` ролью `service_role`, а грантов на эти таблицы у
   роли не было. PostgREST отвечал `403 permission denied for table`, функция
   переводила это в `not_in_room`, игрок видел «Недоступен».
   Починено: `supabase/migrations/livekit_token_grants.sql`, применено на проде.
   ⚠️ Это **гранты, а не RLS**: `service_role` обходит политики строк, но обход
   RLS не даёт привилегий на таблицу. Любая новая таблица, которую читает Edge
   Function, требует явного `GRANT`.

2. **Сессия умирала при старте игры.** `VoiceControl` был только в
   `LobbyScreen`, а `useVoiceChat` при размонтировании вызывает `disconnect()`.
   Старт игры уводит на `/game`, лобби размонтируется, канал рвался.
   Починено: `src/features/voice/VoiceProvider.tsx` держит сессию **над
   роутером**, `VoiceControl` берёт её из контекста через `useVoice()`.

3. **Причина отказа больше не теряется.** `fetchVoiceToken` возвращает
   `{ ok: false, reason }` с 11 различимыми причинами (`voice.reason_*`, девять
   локалей), а не голый `null`. Неудачное чтение на сервере — `503
   lookup_failed`, а не `403`.

## Твоя задача: звук не воспроизводится

**Симптом от заказчика:** «пишет, что всё подключено, но ничего не слышно».
То есть статус `on`, токен выдан, LiveKit соединился — а звука нет.

**Главный подозреваемый, проверен грепом.** В `src/features/voice/useVoiceChat.ts`
обрабатываются ровно два события:

```ts
room.on(RoomEvent.ActiveSpeakersChanged, …)
room.on(RoomEvent.Disconnected, …)
```

Нет `RoomEvent.TrackSubscribed`, нет `track.attach()`, и во всей фиче нет ни
одного `<audio>`-элемента (проверено `grep` по `src/features/voice/`).

**LiveKit не воспроизводит удалённый звук сам.** Входящую дорожку надо
прикрепить к DOM: по `TrackSubscribed` вызвать `track.attach()` (он создаёт
`<audio>`) и вставить элемент в документ; по `TrackUnsubscribed` — `detach()` и
убрать. Без этого мы публикуем свой микрофон, получаем чужой — и никуда его не
выводим. Это ровно «подключено, но не слышно».

**Второе, что проверить после этого — политика автовоспроизведения.** Даже
прикреплённый `<audio>` браузер может не запустить без жеста пользователя. У
LiveKit для этого есть `room.startAudio()` (или `canPlaybackAudio` /
`RoomEvent.AudioPlaybackStatusChanged`). Наше подключение происходит **по тапу**
на кнопку, так что жест есть, но в Telegram WebView это надо проверить
отдельно. Если звук заблокирован — показать игроку кнопку «включить звук» и
вызвать `startAudio()` по ней.

**Третье — каналы.** Убедись, что оба собеседника попадают в один канал.
Логика в `supabase/functions/livekit-token/index.ts`: в режиме `1v1` канал
`ss_<roomId>` (общий на комнату), в командном — `ss_<roomId>_<teamId>` (свой у
каждой команды, это намеренно: соперники не должны слышать объясняющего).
Заказчик тестирует **1v1**, там канал общий.

## Как проверять

* `npm run check:voice` — три серверных звена (preflight, доступность функции,
  проверка подписи). На проде даёт 3/3.
* Логи функции: Supabase → Edge Functions → livekit-token → Logs. Коды
  расшифрованы в `supabase/functions/livekit-token/README.md`.
* Логи PostgREST: MCP `get_logs` с `service: "api"` — именно там нашлась
  причина №1, видно `GET | 403 … | Deno/SupabaseEdgeRuntime` рядом с
  `GET | 200 … | Mozilla/…`.
* Тесты токена: `src/features/voice/voiceApi.test.ts` (17 случаев).

⚠️ **Ограничение:** `initData` невозможно подделать снаружи Telegram by design,
поэтому полный путь проверяется только на реальном устройстве. Всё, что можно
проверить снаружи, уже покрыто `check-voice`.

## Правила проекта, которые здесь легко нарушить

* Каждая пользовательская строка — сразу в **девять** локалей
  (ru en es pt fr ar ja ko zh), проверка `node scripts/check-i18n.mjs`; `ar` — RTL.
* Перед PR: `npx tsc --noEmit`, `npm test`, `npm run build`,
  `npm run test:mutation` (порог 80, понижать нельзя).
* Одна ветка от свежего `main`; PR черновиком; не ставить базой другую ветку `claude/*`.
* GitHub Actions регулярно теряет событие `pull_request`: после пуша посмотри
  чеки PR, и если там только Vercel — запусти `ci.yml` через `workflow_dispatch`.
* Секрет в переменной с префиксом `VITE_` попадает в бандл. `VITE_LIVEKIT_URL` —
  это адрес, он публичный и это нормально; ключ и секрет LiveKit живут только в
  секретах Supabase.
