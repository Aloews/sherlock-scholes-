# Промт: онбординг и коллекция по языку игрока

Скопируйте всё ниже в новую сессию.

---

Проект: Telegram Mini App «Шерлок Скоулс», репозиторий `Aloews/sherlock-scholes-`,
основная ветка `main`. React + Vite + Tailwind + Supabase (проект `konoavrduynecxblqfvq`).

Сначала прочитай: `CLAUDE.md`, `docs/MAP.md` §7, `docs/PLAYER_ATTENTION_ANALYSIS.md`
(там замеры, на которых стоит вся эта задача), `supabase/migrations/deck_fame.sql`.

## Жалоба заказчика

> Игрок на французском или корейском видит в коллекции во вкладке «Клубы»
> «Зенит». Он в это никогда не поверит. Нужны легендарные карточки всех типов
> тех языковых групп, в которых они популярны.

## Что уже установлено — не переизмеряй

**1. Коллекция сортируется по русской популярности.**
`src/features/collection/collectionApi.ts:63`:

```ts
.order('pageviews', { ascending: false, nullsFirst: false })
```

`cards.pageviews` — это просмотры **только ру-вики**. Все игроки мира получают
русский рейтинг. Замерено: ранговая корреляция `pageviews` с настоящей
многоязычной осью — **0.172**, средний сдвиг перцентиля **31 пункт**, 55 %
карточек сдвигаются больше чем на 25.

**2. Простая замена поля сортировки на язык НЕ РАБОТАЕТ — данных нет.**
Проверено на проде:

| Категория | Активных | Есть `pageviews_i18n` |
|---|---|---|
| player | 2524 | 2234 (88.5 %) |
| **club** | **431** | **0** |
| term | 87 | 0 |
| stadium | 28 | 0 |
| coach / referee / commentator / woman | 137 | 0 |

Ночной сборщик `docs/cards_pageviews_i18n.py` обрабатывает **только
`category='player'`** — это написано в его собственной документации, первая
строка блока «КАК РАБОТАЕТ».

Отсюда: `fame` у клубов = `GREATEST(ru, max по языкам)`, где второе пусто,
то есть **известность клуба у нас равна его известности в России**. «Зенит»
получает «эпическую» рамку заслуженно по этой шкале и абсурдно по любой другой.

Я пробовал отсортировать клубы по `fr` и по `ko` — получились **одинаковые**
списки (Парма, Эльче, АЕК Афины, Сантос Лагуна), то есть сортировка нулей.
Если просто поменять поле, заказчик увидит именно это вместо «Зенита».

## Порядок работы

**Шаг 1 — собрать языковые просмотры для не-игроков.** В
`docs/cards_pageviews_i18n.py` снять фильтр `category='player'`. Это ~910
карточек; на карточку — один запрос Wikidata + до восьми pageviews. Ночной
бюджет Wikimedia 5000, укладывается в один прогон. Скрипт кэширующий,
идемпотентный и по умолчанию пропускает уже заполненные карточки — для
пересборки есть `--refresh`.

⚠️ Клубы и стадионы резолвятся в Wikidata иначе, чем игроки: у них другой
`P31`, и одноимённые статьи — обычное дело («Зенит» это ещё и астрономический
термин; у карточки «Зенит» в проде фото схемы зенита-надира именно поэтому).
Проверь качество резолва на выборке до массового прогона.

**Шаг 2 — пересчитать `fame`:** `python docs/cards_fame_refresh.py` (ноль
запросов, чистый RPC). Он же пересчитает `tier` и тег `legend`. После этого
рамки редкости у клубов станут осмысленными сами по себе.

**Шаг 3 — сортировать коллекцию по языку зрителя.**
⚠️ Ловушка: `pageviews_i18n->>'fr'` в PostgREST сортируется **как текст**, и
«9» окажется больше «10000». Нужна RPC с приведением к числу, например

```sql
create or replace function collection_page(
  p_lang text, p_limit int, p_offset int, …
) returns setof cards language sql stable as $$
  select * from cards
   where active
   order by greatest(
     coalesce((pageviews_i18n->>p_lang)::bigint, 0),
     coalesce(pageviews, 0)          -- запасной путь, пока язык не собран
   ) desc nulls last, name asc
   limit p_limit offset p_offset;
$$;
```

Запасной путь через `pageviews` обязателен: пока у категории нет языковых
данных, лучше русский порядок, чем случайный.

**Шаг 4 — онбординг.** `src/features/game/onboarding.ts` уже опирается на
`cards.fame` (многоязычную ось), а не на `pageviews` — после шагов 1–2 он
начнёт работать правильно **без правок кода**. Проверь это, а не переписывай.

## Что считать сделанным

Француз и кореец открывают вкладку «Клубы» и видят вверху клубы, известные в их
языковой среде, а не «Зенит». Проверяется запросом: топ-6 клубов по `fr`, по
`ko` и по `ru` должны **различаться** и выглядеть правдоподобно.

## Правила проекта, которые здесь легко нарушить

* Колода — **один фильтр и один предикат** (`docs/MAP.md` §3): `cards_matching`,
  обёртки `pick_random_cards` и `count_deck`. Новый способ выбирать карточки
  заводить нельзя — он разойдётся со счётчиком. Сортировка коллекции идёт мимо
  этого пути и колоду не трогает, но проверь, что не задел предикат.
* Легаси 12-параметрический `pick_random_cards` не удалять: прод зовёт его
  позиционно, удаление один раз уронило живое приложение.
* Каждая пользовательская строка — сразу в девять локалей, `node scripts/check-i18n.mjs`; `ar` — RTL.
* Перед PR: `npx tsc --noEmit`, `npm test`, `npm run build`,
  `npm run test:mutation` (порог 80).
* Одна ветка от свежего `main`; PR черновиком.
* GitHub Actions теряет событие `pull_request` — после пуша проверь чеки, при
  необходимости запусти `ci.yml` через `workflow_dispatch`.

## Смежное, в эту задачу НЕ входит

* **Фото не по карточкам**: «Факел» — горящий факел, «Порту» — торт, «Эвертон» —
  баннер с трибуны, «Ахмат» и «Урал» — заглушки, «Зенит» — астрономическая
  схема. Тот же корень (резолв статьи по совпадению названия), но отдельная
  задача с превью и ручной вычиткой.
* **Вкладка «Последние трансферы» и актуальные составы** — отдельная фича,
  упирается в источник данных.
