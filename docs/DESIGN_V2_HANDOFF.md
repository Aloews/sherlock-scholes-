## 2. Инвентарь макета: что есть в прототипе, чего нет в приложении

Прототип (`docs/design/reference-prototype.dc.html`) — это цельное приложение
с фазами `splash → onboarding → app` и **нижней таб-навигацией** из четырёх
вкладок. Приложение сейчас — набор роутов без таб-бара.

### 2.1. Каркас

| Элемент макета | Есть в приложении? |
|---|---|
| Нижний таб-бар: Главная · Карты · Рейтинг · Профиль (`rgba(10,14,26,.92)` + `backdrop-filter: blur(10px)`, иконка 21px + подпись 9.5px, активная `#FF8A3D`) | **нет** |
| Оверлеи поверх таб-бара (режим, настройки, join, лобби, игра, результаты, досье, задания) — `position:absolute; inset:0`, анимация `slideUp .25s` / `fadeIn .2s` | частично, как отдельные роуты |
| Splash с градиентным вордмарком и спиннером | нет (есть простой лоадер в `App.tsx`) |
| Онбординг: 4 слайда, иконка в скруглённом квадрате 104px, точки-индикаторы | есть `TutorialScreen`, но другой вёрстки |

### 2.2. Главный экран (`isHome`)

Сверху вниз: «С возвращением, {имя}» + чип серии (🔥 + число) + аватар-квадрат
38px → две кнопки (градиентная 58px «Создать игру», аутлайн 52px
«Присоединиться») → карточка «Ежедневные задания» с прогрессом → полоса из трёх
статов с **градиентными цифрами** (Playfair 800, 20px) → блок «Новое досье» с
карточкой-градиентной рамкой, OVR-квадратом 52px и именем.

Сейчас на главной: логотип-герой, статы 4-в-ряд, три кнопки, ротатор цитат.

### 2.3. Игровой экран (`isGame`)

Круговой таймер 102px (`stroke #FF8A3D`, ширина 5) с числом Playfair 800 32px в
центре → «N угадано» + всплывающее `+1` → строка серии → **карточка**:
градиентная рамка по редкости, внутренний фон `linear-gradient(180deg,#161d30,#0c0f1c)`,
верхняя полоса 4px, иконка категории в квадрате 44px, имя Playfair 26px,
категория капсом, блок «Нельзя говорить» с зачёркнутыми чипами → точки прогресса
→ две кнопки внизу (аутлайн «Пропустить» / градиент «Угадали»).

Сейчас: `PlayerCard` другой структуры, таймер `Timer.tsx` другой геометрии,
запрещённых слов на карточке нет.

### 2.4. Результаты (`isResults`)

Кубок 48px → подпись капсом → имя победителя **градиентным текстом** Playfair 26px
→ строка счёта → карточки команд с левой градиентной полосой 3px у победителя.

### 2.5. Досье карточки (`isPlayer`)

Полноэкранный оверлей: шапка «Досье №…» → карточка с рамкой по редкости, фото
180px, OVR-квадратом → 4 плитки быстрых фактов → «Характеристики» — **6 полос
прогресса 0–100** → трофеи → карьера → факты.

### 2.6. Рейтинг (`isRating`) и Профиль (`isProfile`)

Рейтинг: сегмент-контрол (Друзья/Глобально/Неделя) + строки лидерборда с рангом,
инициалами, очками и дельтой (▲/▼).
Профиль: аватар 64px, «Уровень 12 · Детектив-инспектор», полоса прогресса,
3 стата, горизонтальная лента достижений, список настроек.

## 3. ⚠ Главное: половина макета не имеет данных

Это надо решить **до** кодинга. В схеме (`supabase/schema.sql`) есть только:
`users`, `players`, `player_stats`, `rooms`, `teams`, `room_players`, `rounds`,
`round_cards`, `scores`, `cards`.

| Экран/блок макета | Нужные данные | Есть? |
|---|---|---|
| Статы на главной (игр/побед/очков) | `player_stats` | **да** |
| Рейтинг / лидерборд | таблица рейтинга, дельта за период | **нет** |
| Уровень и звание в профиле | уровень, XP | **нет** |
| Достижения | таблица достижений + прогресс | **нет** |
| Ежедневные задания, серия (streak) | таблица заданий, streak по дням | **нет** |
| OVR карточки (число 96) | рейтинг карты 0–100 | **нет** |
| «Характеристики» в досье (6 полос) | атрибуты игрока 0–100 | **нет** |
| Запрещённые слова на карточке | `cards.forbidden_words` | **да** |
| Редкость, категория, фото, карьера, факты | `cards.*` | **да** |

Варианты по каждому блоку без данных: **(а)** выкинуть из порта, **(б)** сделать
на существующих данных суррогат (например, OVR = производная от `pageviews`/
`tier`), **(в)** заводить миграции и серверную часть — это отдельный проект,
не дизайн-тема.

**Рекомендация:** для «переключаемой темы» брать только (а) и (б). Рейтинг,
достижения, задания, уровни — это новые *фичи*, а не оформление; тянуть их в
задачу про тему значит растянуть её в разы.

## 4. Архитектура: как сделать переключаемым layout, а не только токены

Сейчас один компонент на экран, тема меняет только переменные. Для layout так
не выйдет — структура разная. Три варианта:

### Вариант A — вариант экрана на дизайн (рекомендуется)

```
src/screens/home/HomeScreen.tsx        // выбирает вариант по useDesign()
src/screens/home/HomeScreen.classic.tsx
src/screens/home/HomeScreen.master.tsx
src/features/home/useHome.ts           // ВСЯ логика: состояние, запросы, обработчики
```

Роутер и вся логика не знают о дизайне. Оба варианта получают один и тот же
объект из хука и только рисуют. Плюсы: `classic` физически невозможно сломать,
варианты читаются по отдельности. Минусы: логику из экранов придётся вынести в
хуки — это и есть основная часть работы.

`master`-вариант грузить лениво (`lazy`), чтобы не тащить оба в бандл.

### Вариант B — общий примитив-каркас

Один компонент, но каркас (`<Screen>`, `<AppShell>`, `<Card>`) имеет варианты по
дизайну. Меньше дублирования, но там, где порядок блоков разный (главная), всё
равно упрётесь в ветвления `design === 'master' ? … : …` прямо в JSX — быстро
превращается в кашу.

### Вариант C — только master, classic выпилить

Самое дешёвое, но противоречит задаче «переключаемая тема».

**Берите A.** И порядок такой: сначала вынести логику в хуки (рефакторинг без
изменения поведения, проверяется тем, что `classic` выглядит идентично), потом
рисовать `master`-варианты.

### Таб-бар — отдельный вопрос

Таб-бар меняет *навигационную модель*, а не только вид экрана. Он должен жить в
`AppShell` над `<Routes>`, рендериться только при `design === 'master'` и только
на «корневых» роутах (не в игре/лобби). Вкладки → роуты: Главная `/`,
Карты `/collection`, Рейтинг `/rating` (нет данных — см. §3), Профиль
`/profile` (нет данных).

Если Рейтинг и Профиль выкинуть, таб-бар вырождается в две вкладки — тогда,
возможно, его не стоит делать вовсе. **Это решение за заказчиком.**

## 6. Правила

- **`classic` не меняется.** Любой diff, меняющий вид classic, — баг.
- **Цвета только через токены.** Хардкод `#FF8A3D` в компоненте — баг; берите
  `brand-accent` / `var(--brand-accent)`. Исключения — цвета-данные
  (`CATEGORY_COLOR`, `TIER_COLOR`, цвета команд, статусы), см.
  `docs/DESIGN_SYSTEM.md`.
- **i18n во все девять локалей**, не только ru/en (`src/shared/i18n/locales/`).
- **Не копировать разметку прототипа.** Инлайн-стили оттуда — референс; писать
  на Tailwind по конвенциям репозитория.
- **Токены репозитория побеждают.** Если инлайн-стиль прототипа расходится с
  `tailwind.config.ts` / `index.css` — прав репозиторий.
- `npm run typecheck` и `npm run build` должны проходить.

## 7. Как проверять визуально

Сеть в песочнице закрыта, но продакшн-сборка проверяется локально. Рабочий
рецепт (им проверялся PR #8):

```bash
printf 'VITE_SUPABASE_URL=https://example.supabase.co\nVITE_SUPABASE_ANON_KEY=dummy\n' > .env.local
npm run build && npx vite preview --port 5179 --outDir dist &
```

Дальше Playwright (`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`),
viewport 390×844. Полезное:

- `localStorage.sherlock_tutorial_seen = 'true'` — иначе редирект на туториал;
- `localStorage.sherlock_settings = {"state":{"design":"master"},"version":6}` —
  задать дизайн до загрузки через `context.addInitScript`;
- запросы к Supabase перехватывать через `context.route('**/rest/v1/cards*', …)`
  и отдавать фикстуры. **Внимание:** в Playwright выигрывает обработчик,
  зарегистрированный **последним**, — catch-all регистрируйте первым;
- проверять не только вид, но и `document.documentElement.dataset.design` и
  `getComputedStyle(document.documentElement).getPropertyValue('--brand-accent')`.

Шрифты Google в песочнице не грузятся — Playfair подменяется на Georgia. Это
нормально, на превью Vercel шрифт настоящий.
