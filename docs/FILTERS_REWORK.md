# Переработка фильтров быстрой игры — бриф и промпт для отдельной сессии

> Цель этого файла — дать НОВОЙ сессии полный контекст, чтобы **целостно
> переработать экран выбора колоды** (`HomeScreen`, режим `create_training`),
> а не добавлять ещё один фильтр поверх. Проблема: фильтры прирастали по одному
> (теги → континенты → категории → страна → лига → сложность), каждый прикручен
> отдельно, единой модели и UX нет.

---

## 1. TL;DR — что не так и что нужно

- Фильтров уже **7 независимых групп**, прикрученных в разное время, без единой
  структуры и с пересечениями по смыслу (звёзды / легенды / «сложность» — всё
  про известность).
- Экран — это плоский список чипов (`CHIPS`) + два `<select>` + ряд «сложности».
  Нет группировки, нет иерархии, игрок не понимает модель.
- Часть данных под фильтрами грязная (лиги содержат кубки; «сложность» = tier —
  это прокси, а не явная шкала).
- **Задача новой сессии:** спроектировать и внедрить связный экран фильтров
  с понятными разделами и единой моделью; попутно почистить данные под ними.
  НЕ добавлять новые фильтры поверх — переосмыслить целиком.

## 2. Текущее состояние (аудит)

### 2.1 Где это в коде
- **UI + состояние:** `src/screens/HomeScreen.tsx` (view `create_training`).
- **Проброс в игру:** `HomeScreen.startTraining()` → `navigate('/training', {state})`
  → `TrainingScreen` (`TrainingState`) → `useTraining(...)`
  → `src/features/game/cardRandomizer.ts` (`pickRandomCards` / `rpcPickRandomCards`)
  → RPC `public.pick_random_cards`.
- **Счётчик «Выбрано: N»:** `cardRandomizer.countDeck(...)` (зеркалит WHERE RPC
  через отдельные head-запросы; ЛЮБОЙ новый фильтр надо дублировать и здесь).
- **RPC:** `supabase/migrations/pick_random_cards_tiers.sql` (последняя версия,
  на проде). Одна каноническая функция, все параметры кроме `p_count` = NULL по
  умолчанию (важно: не плодить перегрузки — PostgREST выберет неоднозначно).

### 2.2 Текущие фильтры (7 групп)
| Группа | UI в HomeScreen | RPC-параметр | Что фильтрует |
|---|---|---|---|
| Категории карт (не-игроки) | чипы `CATEGORY_CHIPS` (`NON_PLAYER_CATEGORIES`: club, club_nickname, stadium, term, position, referee, coach, commentator, woman, derby, trophy, era) | `p_categories` | добавляет эти типы карт в колоду |
| Континенты | чипы `CONTINENT_CHIPS` (`ALL_CONTINENT_FILTERS` + `other`) | `p_continents` | игроков по континенту |
| Теги/подборки | чипы `TAG_CHIPS`: star, legend, ballon_dor, goalkeeper, world_cup, wc2026, giant, dwarf | `p_tags` | игроков по тегу (`tags && p_tags`) |
| Страна | `<select>` `selCountry` | `p_countries` | игроков по точной стране (ISO) |
| Лига | `<select>` `selLeague` | `p_leagues` | игроков по `cards.top_league` |
| Сложность/узнаваемость | чипы `TIER_LEVELS`: easy(legendary+epic) / medium(rare) / hard(common) | `p_tiers` | игроков по `cards.tier` |
| Онбординг-сложность (авто) | не в UI, только дефолтная игра | `p_difficulty` (+ `p_boost_countries`, `p_lang`) | порог по pageviews для новичков |

### 2.3 Логика сборки колоды (важные нюансы)
- Колода = **UNION двух пулов**: игроки (когда выбран хоть один континент или
  тег) + выбранные не-игровые категории. Смотри `pickRandomCards` (ветка
  `tags?.length && nonPlayerCats.length` тянет два пула и мешает).
- `everything` (всё выбрано) → шлём `p_categories=null` (вся колода).
- Первый тап по ТЕГУ на «чистом» дефолте фокусирует колоду только на теге
  (`touched`/`tagMode`) — спец-логика, легко ломается.
- RPC применяет фильтры игроков только к `category='player'` (не-игроки
  проходят). `category='woman'` при этом ОБХОДИТ continent/country/league/tier
  (условие `category <> 'player'`), это баг-ловушка.
- Все опциональные RPC-параметры имеют graceful-degrade: при `PGRST202`
  фронт выкидывает параметр и повторяет (`rpcSupportsGeo`, `isMissingGeoParams`,
  и т.п.). Сохранить этот паттерн при переработке.

## 3. Проблемы (почему «прирастает, но не чинится»)

1. **Нет единой модели.** 7 групп прикручены независимо; игрок не понимает, что
   с чем комбинируется. «Категории» = типы КАРТ (клубы/стадионы), а игроки
   выбираются неявно через континенты/теги — противоречивая ментальная модель.
2. **Пересечения по смыслу.** `star` (55 действующих звёзд), `legend` (24),
   и «сложность» easy (legendary+epic) — всё про известность, три разных
   механизма. `p_difficulty` (pageviews) — ЧЕТВЁРТАЯ ось известности.
3. **Грязные данные под фильтрами.**
   - `top_league` включает КУБКИ и еврокубки (FA Cup, DFB Pokal, Coppa Italia,
     League Cup, Super Cup, UEFA Champions/Europa League, «Friendlies Clubs»,
     «Premier League - Summer Series») — это не лиги. Фильтр по лигам выйдет
     грязным. Причина: берётся лига сезона с макс. минутами, а API-Football
     считает кубки отдельными «лигами».
   - «Сложность» = `tier` — это прокси известности, не явная шкала; у части
     карт tier не совпадает с интуицией.
4. **UX-разнобой.** Чипы + два `<select>` + ряд «сложности» — разные контролы
   без группировки/заголовков.
5. **Дублирование логики.** Каждый фильтр надо держать в 3+ местах: RPC,
   `countDeck`, проброс `HomeScreen→TrainingState→useTraining→cardRandomizer`.
   Ошибиться легко (напр. забыть про `woman`).

## 4. Предлагаемое направление (набросок, финал — за новой сессией)

Сгруппировать экран в **явные секции с заголовками**, единая модель:

1. **Что угадывать** — типы карт явными переключателями: Игроки / Клубы /
   Стадионы / Термины / Судьи / … (игроки — ЯВНЫЙ тумблер, не неявный).
2. **(для игроков) Сложность** — ОДНА понятная шкала: Известные / Средние /
   Редкие. Выбрать один источник истины (tier ИЛИ pageviews-бакеты) и свести
   к нему `star`/`legend`/`p_difficulty`, убрав дубли.
3. **(для игроков) География** — Континент → (опц.) Страна, вложенно.
4. **(для игроков) Клубы и лиги** — top-лига, но по ОЧИЩЕННОМУ полю (только
   домашние дивизионы, без кубков/еврокубков).
5. **Особые подборки** — курируемые теги: Вратари / ЧМ / ЧМ-2026 / Золотой мяч /
   Легенды / Высокие / Низкие.
6. Внизу — «Выбрано: N · M карточек» и Играть.

Требования: одна ментальная модель, минимум пересечений, `woman` не должна
обходить географию/сложность, сохранить graceful-degrade RPC.

## 5. Что почистить в данных (под фильтрами)

- **Лиги:** добавить признак «настоящая лига» или отдельное поле
  `top_division` (домашний высший/первый дивизион), исключив кубки и еврокубки.
  Либо в `cards_fill_top_club_preview.py` фильтровать `stat.league` по
  белому/чёрному списку типов, либо чистить `top_league` пост-фактом SQL-ом
  (маппинг «настоящих» лиг). Источник шума — API-Football статистика по кубкам.
- **Ось известности:** решить tier vs pageviews vs star/legend — оставить ОДНУ
  каноническую шкалу для «сложности», остальные свести к ней или к «подборкам».
- **`star`/`legend`:** сейчас `star` = 55 действующих звёзд (переопределено
  2026-07-27, см. `PENDING_SQL.sql`), `legend` = 24 (мусорный набор — тоже
  просится к переопределению как реальные легенды прошлого).
