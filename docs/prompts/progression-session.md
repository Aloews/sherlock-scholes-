# Промт для новой сессии: прогрессия игрока

Скопируйте всё, что ниже разделителя, в новую сессию Claude Code на этом
репозитории. Спека, на которую он ссылается, — `docs/PROGRESSION_FEATURES_HANDOFF.md`.

---

Реализуй прогрессию игрока в Sherlock Scholes: уровни и опыт, достижения,
рейтинг (лидерборд), ежедневные задания и серию дней.

**Сначала прочитай, в этом порядке:**

1. `docs/PROGRESSION_FEATURES_HANDOFF.md` — основная спека: черновик схемы,
   ограничения, фазы.
2. `docs/DESIGN_SYSTEM.md` — правила дизайн-системы. Они обязательны: в
   приложении две переключаемые темы, `master` и `classic`, и всё новое должно
   выглядеть осмысленно в обеих.
3. `docs/design/reference-prototype.dc.html` — нарисованный дизайн этих
   экранов, секции `isRating`, `isProfile`, `isDaily`. Это **визуальный
   референс**: разметку и инлайн-стили оттуда не копировать, переписывать на
   Tailwind по конвенциям репозитория. Скриншоты — `docs/design/screenshots/`.

**Начни с §1 спеки «Что решить до кодинга» и задай мне эти вопросы.** Там семь
пунктов, от которых зависит вся схема: по чему считается рейтинг, откуда брать
«друзей» (в Telegram нет API списка друзей), формула уровня, что даёт XP,
откуда берутся звания, персональные задания или общие, что обрывает серию и в
каком часовом поясе, и полный список достижений с условиями. Не начинай писать
код, пока я не отвечу — угаданная схема потом дорого переделывается.

**Дальше иди по фазам из §5, каждая — отдельный PR:**
уровни и XP → достижения → рейтинг → задания и серия.
Не пытайся сделать всё одним PR.

**Жёсткие требования:**

- **Начисление только на сервере.** XP, разблокировка достижений, прогресс
  заданий, серия — всё через RPC с `security definer`. Клиентский инкремент
  подделывается в одну строку из консоли.
- **RLS на новых таблицах.** Посмотри `supabase/migrations/rls_lockdown.sql` и
  закрой новые таблицы так же: игрок читает свой прогресс и общий лидерборд, но
  не пишет себе ничего.
- **Миграции не применяй сам** — клади `.sql` в `supabase/migrations/` по
  именованию соседних файлов, я выполню их в SQL-редакторе Supabase.
- **Названия достижений и заданий — в i18n, не в БД.** В таблице только `code`,
  подпись по ключу из локали. В приложении девять языков; контент в базе
  пришлось бы переводить руками.
- **i18n во все девять локалей** (`src/shared/i18n/locales/`), не только ru/en.
- **Цвета только через токены** дизайн-системы. Хардкод `#FF8A3D` в компоненте —
  баг. Исключения — цвета-данные (`CATEGORY_COLOR`, `TIER_COLOR`, цвета команд,
  статусы), см. `docs/DESIGN_SYSTEM.md`.
- **`classic` не должен измениться.** Любой diff, меняющий его вид, — баг.
- `npm run typecheck` и `npm run build` должны проходить перед каждым коммитом.

**Куда встраиваются экраны.** Рейтинг и Профиль — это недостающие вкладки
нижнего таб-бара: `src/app/TabBar.tsx`, массив `TABS`. Сейчас там три вкладки
(Главная, Карты, Pro), потому что только эти экраны и существуют; добавь свои
туда же и не забудь `TAB_ROUTES` — от него зависит, где таб-бар вообще
показывается.

**Полезные ориентиры в коде:**

- `src/features/game/usePlayerStats.ts` — как читаются данные игрока;
- `src/features/pro/proApi.ts`, `src/features/reports/reportsApi.ts` — образец
  модуля API фичи;
- `src/screens/CollectionScreen.tsx` — ближайший по конвенциям экран
  (загрузка, скелетоны, пустое состояние, ошибка с ретраем);
- `src/shared/store/proStore.ts` — образец zustand-слайса со статусом с сервера.

**Проверка.** Сеть в песочнице закрыта, но продакшн-сборка проверяется локально —
рецепт в `docs/DESIGN_V2_HANDOFF.md` §7 (там же грабли с приоритетом роутов в
Playwright). Проверяй экраны в обеих темах, а не только в `master`.
