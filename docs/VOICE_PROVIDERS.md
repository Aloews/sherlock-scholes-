# Голосовые сервисы: какие есть, что настроить, как проверить

Голос умеет говорить с тремя сервисами: **LiveKit** (то, что работает
сегодня), **Daily.co** и **Agora**. Выбор — одна переменная с каждой стороны.

Быстрый ответ на «что мне добавить»:

```bash
node scripts/check-voice.mjs --vars     # инвентарь: что нужно, что уже есть
npm run check:voice                     # то же плюс четыре проверки по сети
```

`--vars` ничего никуда не ходит — можно запускать без доступа к проекту.

---

## 1. Кто что решает

| Решение | Где | Почему там |
|---|---|---|
| Каким сервисом пользуемся | `VOICE_PROVIDER` — **секрет Supabase** | Секреты есть только у сервера, значит подписать он может только за «свой» сервис. Выбор клиента был бы выбором того, какие ключи мы задействуем. |
| С какого сервиса начинаем | `VITE_VOICE_PROVIDER` — **переменная Vercel** | Определяет, какой SDK попадёт в бандл и какой сервис пробуем первым. |
| Есть ли запасные | `VITE_VOICE_FALLBACK` — **переменная Vercel** | Компилирует все три адаптера, чтобы мёртвый сервис можно было обойти на лету. |
| Какой канал | Только сервер, из базы | Клиент, который может назвать канал, может назвать канал соперников и услышать объясняющего. Это правило старше мультипровайдерности и не меняется. |

Сервер подписывает за тот сервис, который назвал клиент, — если у него есть
ключи (см. #54). Поэтому `VITE_VOICE_PROVIDER` больше не обязан совпадать с
`VOICE_PROVIDER`: серверная переменная осталась значением по умолчанию для тех,
кто ничего не назвал. Несовпадение всё ещё возможно — если сервер не готов
обслуживать запрошенный сервис, — и тогда это `voice.reason_provider_mismatch`,
а с включённым `VITE_VOICE_FALLBACK` ещё и повод перейти к следующему.

### Сервис выбирает комната, а не устройство

Канал существует только внутри одного вендора. Если игрок А остался на
LiveKit, а игрок Б ушёл на Daily — они в разных каналах разных сервисов, оба
видят «Связь есть» и не слышат друг друга. Это худший вид отказа: он выглядит
как успех.

Поэтому решает комната. `rooms.voice_provider` захватывает первый позвонивший,
всем остальным сервер подписывает токен под него — что бы они ни просили.
Захват атомарный (`claim_room_voice_provider`, блокировка строки), переезд —
compare-and-swap (`move_room_voice_provider`), чтобы двое, у кого вендор умер в
одну секунду, дали один переезд, а не перетягивание.

Клиент, у которого join провалился, сообщает **какой сервис** его отверг — без
этого закрепление убивает перебор: сервер продолжал бы подписывать мёртвый
сервис, и клиент получал бы его на каждой ступени. Остальные узнают о переезде
через обычный realtime `UPDATE` на `rooms` и переподключаются сами.

Обе функции недоступны никому, кроме `service_role`. `EXECUTE` по умолчанию
выдан `PUBLIC`, поэтому после `revoke ... from public` его надо **явно вернуть**
роли `service_role` — иначе Edge Function получит permission denied и голос
умрёт у всех. Тот же явный `grant`, что нужен `get_user_status`.

### Перебор сервисов

`VITE_VOICE_FALLBACK=true` — единственное, что его включает. Порядок:
предпочитаемый сервис первым, дальше остальные в каноническом порядке
(`livekit`, `daily`, `agora`), одинаково на всех устройствах.

Переходим к следующему только тогда, когда виноват **сам сервис**: не
загрузился его чанк, он отказал в join, взял токен и замолчал, наш сервер не
смог получить у него credential или не держит для него ключей. Всё остальное —
комната, игрок, наш собственный Edge Function — у всех трёх ответит одинаково,
и лестница останавливается сразу. Отдельно: **отказ в микрофоне обрывает
перебор целиком**, иначе один «нет» превратится в три запроса подряд.

Правила живут в `src/features/voice/failover.ts` рядом со своими тестами.

⚠️ **Чем это платится.** Без флага в `dist/` один SDK-чанк; с флагом — три
(Daily ≈ 260 КБ, LiveKit ≈ 530 КБ, Agora ≈ 1,6 МБ). Это динамические импорты:
на старте не грузится ни один, а второй — только после того, как первый уже
не сработал. Растёт вес сборки, а не время открытия приложения.

## 2. Переменные

Ничего с префиксом `VITE_` не является секретом: Vite вкомпилирует значение в
бандл, и его прочитает любой игрок. Ключи и сертификаты живут **только** в
секретах Supabase.

### Общее

| Переменная | Где | Значение |
|---|---|---|
| `VOICE_PROVIDER` | секрет Supabase | `livekit` \| `daily` \| `agora`. Не задана — `livekit`. Значение по умолчанию для запросов без явного сервиса. |
| `VITE_VOICE_PROVIDER` | Vercel | С какого сервиса начинать. Не задана — `livekit`. |
| `VITE_VOICE_FALLBACK` | Vercel | `true` — везти все три адаптера и обходить мёртвый сервис. Не задана — один адаптер, как раньше. |

### LiveKit

| Переменная | Где | Где взять |
|---|---|---|
| `VITE_LIVEKIT_URL` | Vercel | Страница проекта, `wss://<имя>.livekit.cloud`. Публичный адрес. |
| `LIVEKIT_API_KEY` | секрет Supabase | Settings → Keys. |
| `LIVEKIT_API_SECRET` | секрет Supabase | Показывается один раз рядом с ключом. **Подписывает токены.** |

```bash
supabase secrets set VOICE_PROVIDER=livekit
supabase secrets set LIVEKIT_API_KEY=APIxxxx LIVEKIT_API_SECRET=xxxx
supabase functions deploy livekit-token
```

### Daily.co

| Переменная | Где | Где взять |
|---|---|---|
| `VITE_VOICE_ENABLED` | Vercel | `true`. Daily не требует публичного адреса, поэтому UI включает именно эта переменная. |
| `DAILY_API_KEY` | секрет Supabase | Dashboard → Developers. Создаёт комнаты и выпускает meeting-токены. |
| `DAILY_DOMAIN` | секрет Supabase | `<команда>.daily.co`. |

```bash
supabase secrets set VOICE_PROVIDER=daily
supabase secrets set DAILY_API_KEY=xxxx DAILY_DOMAIN=yourteam.daily.co
supabase functions deploy livekit-token
```

Комнату создаёт сервер, `privacy: private`. Публичная комната Daily открыта
любому, кто узнал URL, — это отменило бы правило каналов целиком.

### Agora

| Переменная | Где | Где взять |
|---|---|---|
| `VITE_VOICE_ENABLED` | Vercel | `true`. App id приезжает вместе с токеном, публично настраивать нечего. |
| `AGORA_APP_ID` | секрет Supabase | Console → Project. Значение публичное, но отдаёт его сервер — чтобы решение было в одном месте. |
| `AGORA_APP_CERTIFICATE` | секрет Supabase | Console → Project → Primary certificate. **Подписывает токены.** |

```bash
supabase secrets set VOICE_PROVIDER=agora
supabase secrets set AGORA_APP_ID=xxxx AGORA_APP_CERTIFICATE=xxxx
supabase functions deploy livekit-token
```

Токен Agora строится библиотекой Agora (`npm:agora-token`), а не руками:
AccessToken2 — упакованная бинарная структура со своей версионностью, и
ошибка в ней даёт токен, который отвергается при входе без единой подсказки.

## 3. Что общего и что различается

Всё, что зависит от сервиса, живёт в `src/features/voice/providers/` — по
адаптеру на сервис. `useVoiceChat` не импортирует ни одного SDK: он знает про
сессию, которую можно заглушить, измерить и закрыть.

| | LiveKit | Daily | Agora |
|---|---|---|---|
| Единица | адрес + канал | **комната-URL** (создаёт сервер) | app id + канал |
| Токен привязан к | каналу | комнате | каналу **и точному uid** |
| Кто делает `<audio>` | SDK (`attach()`) | мы (`AudioSink`) | SDK (внутри себя) |
| Отказ автовоспроизведения | `AudioPlaybackStatusChanged` | отказ `play()` | `onAudioAutoplayFailed` |
| Что даёт лесенке качества | RTT и потери | потери | RTT |
| Видео | **есть** | нет | нет |

Имя канала для Daily и Agora **укорачивается**: каноническое
`ss_<roomId>_<teamId>` — до 76 символов, а Daily ограничивает имя комнаты 41
символом, Agora — 64. Сервер хеширует канонический вариант (SHA-256, первые 20
hex) и отдаёт короткий. Не обрезает: обрезанные UUID сталкиваются
непредсказуемо, 80 бит SHA-256 — нет.

Правило каналов не меняется ни для кого: `1v1` — один канал на комнату,
командный режим — по каналу на команду.

**Видео — свойство адаптера, а не вендора.** `VoiceTransport.video` описывает
то, что умеет *этот код*: Daily и Agora прекрасно возят картинку, но здешние
адаптеры её не публикуют и говорят об этом вслух, а `setCameraEnabled` на них
не молчит, а бросает. Кнопка камеры показывается по сервису, который **реально
подключился** — перебор может увести комнату на аудио-адаптер посреди партии.
Подробности решения — `docs/VIDEOCHAT_HANDOFF.md`, фаза 3.

## 4. Как проверять

Три уровня, от дешёвого к дорогому.

**1. Переменные, без сети.**

```bash
node scripts/check-voice.mjs --vars
```

Печатает, что нужно выбранному провайдеру и что уже есть в этом окружении.
Серверные секреты снаружи не читаются — так и задумано, их подтверждает
следующий шаг.

**2. Сервер, по сети.**

```bash
npm run check:voice
```

Четыре проверки: `preflight` (CORS покрывает то, что реально шлёт supabase-js),
`reachable` (функция задеплоена и её секреты на месте — **при 503 ответ
называет, каких именно не хватает**), `identity` (неподписанный `initData`
получает 401), `provider` (обе половины на одном сервисе).

**3. Устройство — в приложении.**

Профиль → **«Проверка звука»**. Это то, до чего скрипт не дотягивается:

* даёт ли Telegram WebView микрофон вообще (`denied` — не дал, `failed` — его
  нет);
* двигается ли полоска, когда вы говорите — микрофон живой;
* «Слышать себя» — воспроизведение через тот же `<audio>` в документе, каким
  идёт чужая дорожка. Если браузер откажет здесь, он откажет и в звонке, и
  сообщение будет то же.

Проверка ничего не отправляет: ни комнаты, ни токена, ни второго игрока. Если
она проходит, а звонок — нет, дело выше устройства.

## 5. Ловушки

* **Сборка без переменных вырезает голос целиком.** Vite подставляет
  `VITE_*` литералами, `voiceEnabled()` сворачивается в `false`, и весь путь
  подключения вместе с `import()` SDK уходит в мёртвый код — чанка сервиса в
  `dist/` не будет вовсе. Это правильно (сборка без голоса за него не платит) и
  выглядит ровно как сломанная сборка. Проверять так:

  ```bash
  VITE_VOICE_PROVIDER=livekit VITE_LIVEKIT_URL="wss://…" npm run build
  ```

  Тот же механизм работает и в плюс: в бандл попадает **только выбранный**
  адаптер со своим SDK. Замерено сборкой:

  | `VITE_VOICE_PROVIDER` | SDK-чанк в `dist/assets/` |
  |---|---|
  | не задан, голоса нет | *нет ни одного* |
  | `livekit` | `livekit-client.esm-*.js` |
  | `daily` | `daily-esm-*.js` |
  | `agora` | `AgoraRTC_N-production-*.js` |

  Держится это на двух мелочах в `providers/index.ts`, и обе легко сломать:
  сравнение идёт с **сырым литералом** `import.meta.env.VITE_VOICE_PROVIDER`
  (вызов `voiceProvider()` не сворачивается, и тогда в сборку попадут все
  три), и это **`if`, а не `switch`** — Rollup выкидывает мёртвые ветки `if` и
  не выкидывает мёртвые `case`. Версия со `switch` собирала все три SDK.

* **Функция называется `livekit-token`, а выдаёт токены всем троим.** Имя
  историческое: по нему ходят уже задеплоенные фронты, а переименование живой
  точки входа этот проект однажды уже уронил (`pick_random_cards`, CLAUDE.md).
  Переименовывать — когда будет окно на обе половины сразу.

* **Новая таблица, которую читает Edge Function, требует явного `GRANT`.**
  `service_role` обходит RLS, но обход RLS не выдаёт привилегий на таблицу. Это
  и был баг №1 в `docs/LOBBY_AND_VOICE_FIXES.md` §3.

* **Adapters Daily и Agora ещё не гоняли на живых аккаунтах.** Написаны по
  документации сервисов и покрыты юнит-тестами на подставных SDK; серверную
  половину проверяет `check:voice`. Первая настоящая сессия — то, что
  подтвердит остальное.
